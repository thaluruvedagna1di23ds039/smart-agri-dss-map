# Smart Agriculture Decision Support System (map-click edition)

Final-year project: log in, **click a point on the map**, and the system fetches
the weather and soil for that point by itself and returns:

1. **Crop yield prediction** (RandomForest) for 12 crops, ranked by suitability, shown next to
   **real historical yields** (India APY data) for the clicked district/state
2. **Intercrop recommendations** (rule-based, explainable)
3. **Crop rotation plan** (4 seasons; no same family back-to-back, legume after heavy feeders)
4. **Nutrient recovery estimate** from farmyard manure, compost, vermicompost and poultry manure
5. **History** of each user's analyses (private per user)

No manual data entry is needed for the analysis. Typing happens only at register/login.

## Run it

```bash
python -m venv venv
venv\Scripts\activate            # Windows   (Linux/Mac: source venv/bin/activate)
pip install -r requirements.txt
python train.py                  # trains the yield model (also happens automatically on first run)
python app.py                    # open http://127.0.0.1:5000
python test_app.py               # optional: automated end-to-end test (network mocked)
```
Needs internet at run time (map tiles, weather, soil, region lookup).

## Authentication & security

Passwords hashed (Werkzeug PBKDF2), session cookies HttpOnly + SameSite, CSRF token on every POST,
login lock-out after 5 failures/10 min, parameterised SQL, per-user history, results rendered with
`textContent` (no XSS). For real deployment: use HTTPS, a production server (gunicorn/waitress) and set `SECRET_KEY`.

## Honest limitations (say these in your viva)

* **The yield model is trained on a synthetic dataset** generated by an agronomic response function
  (R² 0.89 is agreement with that function, *not* field accuracy). APY has no weather/soil/coordinates,
  so it cannot train a map-based model directly. It is used to show real past yields beside the prediction.
  For a stronger project: join APY to district-level weather/soil yourself, then `python train.py --csv joined.csv`.
* Weather is the last 12 months' annual mean/total, not season-specific.
* Soil phosphorus and potassium are not available from SoilGrids, so they are not model inputs.
* APY has no tomato records; cotton is converted from bales/ha (170 kg/bale) to lint t/ha.
* Rotation is for generic seasons, and nutrient recovery uses a standard 5 t/ha application.
* Region lookup works for India only; elsewhere the yield columns show "n/a".
